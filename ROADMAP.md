## Phases

- [x] **Phase 0 (done, not a code phase) — confirm deployment model + sequencing.** Resolved 2026-10-22, user-confirmed:
  - **Deployment model: both shapes, not a choice between them.** `hrb_chatbot_service` already runs both live today - a sync in-request path (any vector store) and a real S3->SQS->Lambda async path (Pinecone-only, Phase 88/89, verified live on AWS). This repo targets both, built across 2 phases (Phase 1 sync/container, Phase 2 async/Lambda) rather than in one shot.
  - **Sequencing override.** `hrb_chatbot_service`'s own `docs/dev-reference/microservices-rollout-plan.html` sequences this split *after* the API Gateway's production cutover (ingestion flagged there as the highest-risk piece). User chose to build this first anyway - Gateway cutover stays parked. Recorded here, not silently deviated from.
  - **Stale-docs finding, not yet fixed (flagged, out of this repo's own scope to fix):** `hrb_chatbot_service`'s `CLAUDE.md` and its own `docs/dev-reference/rag-ingestion/architecture.html` both still describe the Lambda/async path as "design only, not implemented" - that's stale, predates Phase 88/89, never updated. Worth fixing in that repo, not this one.

- [x] **Phase 2 (done) — async/Lambda pipeline extraction.** Port `lambda_handlers/index_document_handler.py` so this repo's own pipeline (Phase 1) also runs as a Lambda, triggered by an S3 upload via SQS - the second deployment shape Phase 0 committed to.
  - **Spec:**
    - **Context:** Phase 1 built the sync/container path and everything the Lambda handler calls into (`pipeline.index_document()`, `DocumentMetadataStore`). This phase is a thin adapter on top of that - no new pipeline logic, just a different trigger.
    - **Source:** `hrb_chatbot_service`'s `src/hrb_chatbot/lambda_handlers/index_document_handler.py` (193 lines) - reads one SQS batch (each message wrapping an S3 `ObjectCreated` event), downloads the object to `/tmp`, calls `pipeline.index_document()`, reports per-message failures via AWS's `batchItemFailures` pattern so one bad document doesn't block the rest of the batch. Plus `.github/workflows/deploy-lambda.yml` (separate from the main app's own deploy workflow - different image, different AWS target) and `Dockerfile.lambda` (not yet read in detail - read before porting) for the deploy-prep half. Tests from `tests/hrb_chatbot/lambda_handlers/test_index_document_handler.py` (305 lines).
    - **API surface:** `src/rag_ingestion/lambda_handler.py` - `lambda_handler(event, context)`, same shape (`_parse_s3_event`, `_document_id_and_filename`, `_pending_overrides_kwargs`, `_index_one`, `_process_one_record`, `_process_batch`, the JSON log formatter). `Dockerfile.lambda` and `.github/workflows/deploy-lambda.yml` mirrored from the originals, pointing at this repo's own image/function names (not yet picked - flagged below).
    - **The one real adaptation:** the original calls `pipeline.index_document()` without a `metadata_store` argument - it reaches one via `get_db_gateway().metadata_store()` internally. This repo's own ported `pipeline.index_document()` (Phase 1) takes `metadata_store` as an explicit first argument instead (dependency injection, no `db_gateway` in this repo). The Lambda handler builds one `DocumentMetadataStore()` (via `get_metadata_store()`) and passes it through, same as `documents/routes.py` already does for the sync path.
    - **Behavior parity:** the 305-line test file ports with fakes for S3 (`boto3.client("s3")`), the metadata store, and `pipeline.index_document()` - no real AWS call in any test, matching Phase 1's own testing convention and this repo's `conftest.py` fakes (extend them, don't duplicate).
    - **Out of scope:** real AWS provisioning - no Lambda function, ECR repo, SQS queue, or S3 bucket/event-notification actually created. Matches the split `hrb_api_gateway_service`'s own Phase 8 already used (deploy-prep now, real cutover later, its own explicit go-ahead). Also out of scope: picking real image/function/queue/bucket names - placeholder values only until that go-ahead conversation happens.
